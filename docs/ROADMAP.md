# 路线图 / Roadmap

这份文档说明 Spoor 往哪走，以及**明确不走哪**。

最后更新：2026-10-11

---

## 项目定位

**一个本地的阅读与批注工具。**

导入 PDF 或 EPUB → 和书里的内容对话 → 标注高亮、划词翻译 → 把值得留下的段落摘成画布上的卡。

核心判断：大多数 AI 阅读工具停留在"和 PDF 聊天"，输出停在聊天框里。这里不一样的是——
**阅读产生的每一条结论都落到画布上**，变成可以移动、连接、继续追问的东西。

配套的立场是**本地优先**：画布数据存在 IndexedDB，API 密钥只存本地，端侧 OCR 不上传照片。
没有账号也能用完整个流程。

---

## 为什么收窄到这个范围

这个项目曾经以"什么都能做的 AI 画布"为叙事，结果是评审看不出它解决什么问题，
用户也说不清什么时候该打开它。收窄不是为了变小，是为了能被说清楚。

已经存在但**不在主线内**的能力（它们仍然能用，只是不作为卖点）：

- 通用便签、主题卡、Agent 卡
- 随笔 / 长文编辑器
- Pocket 拍照与端侧 OCR（作为阅读的随手记入口）
- 工作区与多角色房间（作为摘抄的落点与组织方式）

## 接下来

按优先级，不承诺具体日期——这是单人维护，日期承诺通常兑现不了。

### 优先：让主线更可靠

- **修掉已知的 3 个失败测试**（主题卡断言，主题卡重设计后遗留）
- **给"摘抄成卡"补端到端测试**：目前这条关键路径只有单元测试，缺一个"导入 EPUB → 摘抄 → 卡片出现在画布上"的集成用例
- **修阅读体验里已知的问题**：长章节滚动定位、摘抄上限（200 条）触发时的行为

### 其次：让主线更好用

- **摘抄的导出**：Markdown / EPUB 批注格式。现在摘抄只能留在画布上，出不去
- **多本书的整理视图**：一本书一个书卡，摘抄散在画布上，缺一个按书归档的入口
- **划词翻译的批量模式**：现在一次一句

### 之后：看情况

- **更多格式**（MOBI、DOCX 书籍化）——只在有人提需求时做
- **插件接口**——让社区扩展查词源、导入格式。**这是最需要外部输入的一块，也是最不确定的一块**，先不动

## 明确不做

| 不做 | 原因 |
|---|---|
| 服务端与账号 | 与本地优先的前提冲突 |
| 实时协作 | 同上 |
| macOS / Linux 桌面版 | 桌面壳里的本地推理与语音代理在别的平台未验证。与其发跑不动的包，不如不发 |
| 移动端 App | 工作量等于再做一个项目 |
| 内置模型托管 | 用户用自己的密钥，或桌面端接本地 GGUF |
| 遥测与数据上报 | 与"数据不离开设备"的承诺冲突 |

## 版本节奏

诚实地说：**目前没有稳定的发版节奏。** v0.1.0（2026-05）之后，v0.2.0（2026-09）隔了三个多月，
之后到 2026-10 合并了大量功能但仍未发版。

打算改成一个弱得多但能兑现的承诺：

- **按季度看一次**，有值得给的东西就发，不凑数
- **每次发版只讲一件能演示的事**（例："v0.3 — EPUB 导入到摘抄成卡的全流程"）
- **不承诺具体日期。** 单人维护下，日期承诺只会变成一次次跳票

发版记录见 [Releases](https://github.com/iimorning/spoor/releases)。
